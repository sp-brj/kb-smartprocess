## Открытый техдолг (не сделано)

Приоритет сверху вниз.

- [ ] **Rate-limit только in-memory.** На Vercel serverless инстансы не делят память → защита
      частичная. Нужен Upstash Redis + `@upstash/ratelimit` (`src/lib/rate-limit.ts`).
- [ ] **`share-DELETE` без ownership**: любой залогиненный деактивирует любую share-ссылку.
      Требует поля `createdBy` в `ShareLink`/`FolderShareLink` + миграция.
- [ ] **MCP-сервер нестабилен**: `verify=False` в 5 httpx-клиентах (MITM-риск), новый клиент на
      каждый запрос без пула, единый timeout, нет retry — это и есть корень багов из
      `BACKLOG-MCP-API.md` («падает на записи», «list_tags роняет транспорт»).
- [ ] **Нет пагинации и `select`** в list-эндпоинтах — тянут все статьи с полным `content`
      (`/api/articles` и др.); N+1 в reindex. Растёт вместе с базой.
- [ ] **~300 строк дублей**: `ShareButton` (316) ≈ `FolderShareButton` (306). Merge отложен —
      нет E2E на share-флоу, риск сломать молча.
- [ ] **Рассогласование версий**: `react@18` при `@types/react@19`, `eslint-config-next@16` при `next@15`.
- [ ] **0 unit-тестов** (только E2E).
- [ ] Ветки-хвосты в git: `feature/collapsible-sidebar`, `chore/migrate-on-prod-build`.

## Инфраструктура вне кода (на стороне Vercel/Supabase)

**Preview-деплой Vercel падает на каждом PR** — `prisma migrate deploy` не достучится до
preview-БД: `FATAL: (ENOTFOUND) tenant/user postgres.svxojrtoyjjrqcylruzg not found`.

- Прод **не затронут**: preview указывает на отдельный Supabase-проект, прод-`DATABASE_URL` валиден.
  Главная тревога аудита («preview накатит миграции с `TRUNCATE ArticleChunk` на прод») **не подтвердилась**.
- Причина: preview-проект Supabase, вероятно, поставлен на паузу за неактивность (free tier).
- Лечится одним из двух: Restore проекта в Supabase (или новый + обновить `DATABASE_URL` для
  окружения Preview), либо вернуть `scripts/vercel-build.sh` к «мигрировать только на production».
- ⚠️ Если включать branch protection с обязательным Vercel-чеком — сначала починить, иначе
  всегда-красный preview заблокирует мерж любых PR.

**Деструктивная миграция** `20260526120000_change_embedding_dim` делает `TRUNCATE ArticleChunk` —
после её накатки AI-поиск молча пустой, пока не запустить переиндексацию вручную. Авто-хука нет.
